# Publishing AgentBridge releases

The release workflow builds self-contained macOS Apple Silicon, Linux x86-64 and Windows x86-64 archives. It tests the packaged gateway and dashboard on each target runner before attaching the archives and individual SHA-256 files to a GitHub Release. A manual workflow run builds downloadable CI artifacts without publishing a release.

Before publishing, merge the changes to the default branch and run the workflow manually. Test the resulting packages on actual desktops, especially macOS login startup, the tray on Linux X11 and Windows, CLI provider detection, and installation/upgrades. On macOS, log out and back in, confirm both the gateway and visible status indicator start, and check the LaunchAgent's last exit code and `~/.agentbridge/autostart.log`. Test recovery after stopping the helper, and verify repeated starts do not duplicate it. The CI smoke test uses `--no-tray`; it checks that the macOS helper is packaged but does not verify an interactive system tray, login startup, or provider login.

When ready, create and push a version tag on the reviewed commit, for example `v0.3.2`. The tag starts `.github/workflows/release.yml` and sets the CLI and dashboard version in each release build automatically; no source version edit is needed. The tag must use the stable `vMAJOR.MINOR.PATCH` format and should be greater than the previous release. The release is created only if all three builds and the full CI workflow succeed on the tagged commit. The GitHub page reads the latest published release dynamically. The installers use the GitHub repository configured in the scripts and fetch assets from its latest release. For forks, set `AGENTBRIDGE_REPOSITORY=owner/repo` before invoking the installer or change the default repository and README URLs.

The SHA-256 files detect download errors but, because they come from the same release as the archives, they do not independently authenticate the publisher. Release binaries are currently unsigned. Configure Apple Developer signing/notarization and Windows code signing before presenting releases as signed or trusted by the platform. Source scripts are also downloaded and executed by the one-command instructions; users can inspect and run them locally instead.

The installers preserve old release directories and launcher backups. They do not stop a running gateway, automatically restart it, or remove user data. To uninstall, run `agentbridge uninstall`; it stops the managed gateway and removes the verified launcher and installer-managed release directories. The source checkout and launcher backups are retained. User data in `~/.agentbridge` (or `AGENTBRIDGE_HOME`) remains unless `agentbridge uninstall --purge` is used. On Windows, removal of a packaged installation runs after the command exits; check the printed log for the outcome. Custom install locations require the same `AGENTBRIDGE_INSTALL_ROOT` and `AGENTBRIDGE_BIN_DIR` settings used during installation.
