# Publishing AgentBridge releases

The release workflow builds self-contained macOS Apple Silicon, Linux x86-64 and Windows x86-64 archives. It tests the packaged gateway and dashboard on each target runner before attaching the archives and individual SHA-256 files to a GitHub Release. A manual workflow run builds downloadable CI artifacts without publishing a release.

Before publishing, merge the changes to the default branch and run the workflow manually. Test the resulting packages on actual desktops, especially the tray on Linux X11 and Windows, CLI provider detection, and installation/upgrades. The CI smoke test uses `--no-tray`; it does not verify an interactive system tray or provider login.

When ready, create and push a version tag on the reviewed commit, for example `v0.3.0`. The tag starts `.github/workflows/release.yml` and sets the CLI and dashboard version in each release build automatically; no source version edit is needed. The tag must use the stable `vMAJOR.MINOR.PATCH` format and should be greater than the previous release. The release is created only if all three builds succeed. The GitHub page reads the latest published release dynamically. The installers use the GitHub repository configured in the scripts and fetch assets from its latest release. For forks, set `AGENTBRIDGE_REPOSITORY=owner/repo` before invoking the installer or change the default repository and README URLs.

The SHA-256 files detect download errors but, because they come from the same release as the archives, they do not independently authenticate the publisher. Release binaries are currently unsigned. Configure Apple Developer signing/notarization and Windows code signing before presenting releases as signed or trusted by the platform. Source scripts are also downloaded and executed by the one-command instructions; users can inspect and run them locally instead.

The installers preserve old release directories and launcher backups. They do not stop a running gateway, automatically restart it, or remove user data. To uninstall, run `agentbridge stop`, remove the launcher from the installer's printed directory and remove the AgentBridge release directory (`~/.local/share/agentbridge` on Unix or `%LOCALAPPDATA%\AgentBridge` on Windows). User settings, credentials and data are separate in `~/.agentbridge` and can be removed separately if desired.
